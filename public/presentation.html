Problem Statement & Objectives

ที่มา ปัญหา และวัตถุประสงค์ของโครงการ

⚠️ ปัญหาในระบบทั่วไป (Security Risks)

  • • IDOR / BOLA: พนักงานแอบดูหรือแก้ไขตั๋วแจ้งซ่อมของผู้อื่นได้โดยเปลี่ยน Ticket ID
  • • Vertical Privilege Escalation: ผู้ใช้ทั่วไปแอบเรียก API สิทธิ์ Admin หรือเปลี่ยน Role ตนเอง
  • • Admin Sprawl: การเปิดให้สมัคร Admin ได้ไม่จำกัด ทำให้ตกเป็นเป้าหมายถูกยึดระบบ

🎯 วัตถุประสงค์และการแก้ไข (Our Solutions)

  • ✓ พัฒนาระบบ Service Desk ที่ใช้งานได้จริง ครบวงจร (Tickets, Categories, Comments, Departments)
  • ✓ ออกแบบการป้องกัน Broken Access Control ครอบคลุมทั้งแนวตั้ง (Vertical) และแนวนอน (Horizontal)
  • ✓ บังคับใช้ Single Super Admin Policy ป้องกันการขยายสิทธิ์ และแยกเส้นทาง URL ชัดเจน
System Architecture

สถาปัตยกรรมระบบและการแยกส่วนความปลอดภัย

💻 Presentation Tier

Frontend Dashboards & Portals

  • • Admin Portal: /admin/login, /admin
  • • User Portal: /login, /register
  • • RBAC Dynamic UI: ซ่อนเมนู Settings สำหรับผู้ใช้ที่ไม่ใช่ Admin
⚙️ Application Tier

NestJS Modular Core & Guards

  • • JWT Strategy & AuthGuard: ตรวจสอบ Token ทุก Request
  • • RolesGuard & Decorator: ตรวจสอบสิทธิ์ระดับ Controller และ Method
  • • Ownership Scoping: ตรวจสอบความเป็นเจ้าของตั๋วในระดับ Service Logic
🗄️ Data Tier

PostgreSQL 18 via Prisma ORM

  • • Schema Models: User, Category, Ticket, Comment
  • • Password Hashing: Bcrypt (Salt Rounds 10)
  • • Data Integrity: Foreign Key RESTRICT ป้องกันการลบหมวดหมู่ที่มีตั๋วค้าง
Core Functional Modules

ฟังก์ชันการทำงานหลัก (Collections & Operations)

🎫

Tickets (ตั๋วแจ้งซ่อม)

ติดตามสถานะ (OPEN, IN_PROGRESS, RESOLVED, CLOSED) คัดกรองตามสถานะ ความเร่งด่วน และหมวดหมู่ได้ทันที

📁

Categories (หมวดหมู่)

แสดงจำนวนตั๋วสะสม, คลิกเพื่อกรองดูตั๋วในหมวดนั้นได้, แก้ไข/ลบหมวดหมู่พร้อมระบบป้องกันตั๋วค้าง

💬

Comments (บันทึกงาน)

ระบบความคิดเห็นแยกประเภท (🔒 บันทึกภายใน / 🌐 สาธารณะ) ค้นหาข้อความได้ และเปิดดูตั๋วที่เกี่ยวข้องได้ทันที

🏢

Departments (แผนก)

จัดกลุ่มบุคลากรตามแผนก (Management, IT Operations, Finance, General) แสดงสถิติตั๋ว และกรองตั๋วตามแผนก
