1. ที่มา จุดเด่น และประโยชน์ของสถาปัตยกรรม Amplication

Amplication เป็นแพลตฟอร์ม Open-source ชั้นนำสำหรับสร้าง Backend Services และ APIs (Node.js / NestJS) แบบอัตโนมัติ โดยผสมผสานข้อดีของ Low-Code เข้ากับ Professional Code Generation (ได้โค้ดภาษา TypeScript แท้ 100%)

1.1 จุดเด่นสำคัญ (Key Highlights)

  • Clean Architecture ระดับ Enterprise: ผลิตโค้ด NestJS ที่แยกเป็น Modules, Controllers, Services, DTOs และ Prisma Service อย่างเป็นระเบียบ อ่านเข้าใจง่าย และปรับแต่งต่อยอดได้อย่างอิสระ
  • Type-Safety สูงสุดด้วย Prisma ORM: ใช้ Prisma ในการเชื่อมโยงฐานข้อมูล ทำให้การสืบค้นข้อมูลมี Type-checking ป้องกันข้อผิดพลาดตั้งแต่ตอนเขียนโค้ด
  • ระบบ Authentication & Role-Based Access Control (RBAC): ติดตั้ง Passport-JWT และ Bcrypt Hashing มาตรฐาน พร้อมโครงสร้าง Guard สำหรับจำแนกสิทธิ์ผู้ใช้งาน
  • ไร้ปัญหา Vendor Lock-in: เป็นเจ้าของซอร์สโค้ด 100% สามารถนำไปรันบนเซิร์ฟเวอร์หรือ Cloud ใดก็ได้โดยไม่ต้องพึ่งพา Amplication ในอนาคต

1.2 เปรียบเทียบกับ Strapi 5 (โปรเจกต์ 69-s1-cybersec เดิม)

คุณสมบัติ Strapi 5 (โปรเจกต์เดิม) Amplication (โปรเจกต์ใหม่)
รูปแบบระบบ Headless CMS สำเร็จรูป รันจาก Image Backend Code Generator (NestJS + TypeScript บริสุทธิ์)
การปรับแต่งโค้ด ต้องทำ Monkey Patch ผ่าน Docker Volume Mounts แก้ไข Source Code โดยตรง ใน Controller, Service, DTO
ฐานข้อมูลและ ORM Knex.js / Custom Query Engine Prisma ORM (ทันสมัย Type-Safe และจัดการ Migration ได้ง่าย)
Admin Dashboard มี Built-in Admin Panel ที่พอร์ต 1337 มี Web Service Desk Dashboard + Prisma Studio (พอร์ต 5555)
แนวทางการทดสอบ ใช้ api.http.simple ใน VS Code ใช้ api.http.simple รูปแบบเดียวกันเป๊ะ + Swagger UI

ลำดับขั้นตอนการทำงานร่วมกัน (Team Handover Timeline)

  1. ระยะที่ 1 (คนที่ 1 เริ่มต้น): แตก Branch feat/db → เขียน Docker Postgres + Prisma Schema → รัน Seed ข้อมูล → แตก Branch feat/admin → เพิ่ม pgAdmin ใน Docker Compose (พอร์ต 5050) → Merge เข้าสู่ main
  2. ระยะที่ 2 (คนที่ 2 รับไม้ต่อ): แตก Branch feat/app → สร้าง NestJS App Core เชื่อมต่อกับ DB ของคนที่ 1 → พัฒนาโมดูล Authentication (JWT Strategy, Login, Register, Profile) → Merge เข้าสู่ main
  3. ระยะที่ 3 (คนที่ 3 ดำเนินการขั้นสุดท้าย): แตก Branch feat/rest → พัฒนา CRUD Controllers สำหรับ Tickets, Categories, Comments → จัดทำไฟล์ api.http.simple ที่มีตัวแปร {{$dotenv ...}} ดึง Token และ ID อัตโนมัติ → ทดสอบยิง Request ครบทุกข้อ → Merge เข้าสู่ main

5. การออกแบบ API และโครงสร้างไฟล์ api.http.simple

เพื่อให้การทดสอบตรงกับรูปแบบเดิมใน 69-s1-cybersec/api.http.simple โครงสร้างไฟล์ทดสอบจะถูกแบ่งเป็น 5 หมวดหมู่:

หมวดหมู่ หัวข้อย่อย HTTP Method & Endpoint สิทธิ์ที่ต้องใช้
1. Admin 1.1 Admin Login POST /admin/login ไม่ต้องมี Token (รับ Token กลับมา)
1.2 Admin Profile GET /admin/users/me Bearer Token (Admin)
2. User / Staff 2.1 User Register POST /api/auth/register ไม่ต้องมี Token
2.2 User Login POST /api/auth/login ไม่ต้องมี Token (รับ Token กลับมา)
2.3 User Profile GET /api/users/me Bearer Token (User)
3. Categories 3.1 List Categories GET /api/categories Bearer Token
3.2 Create Category POST /api/categories Bearer Token (Admin Only)
4. Tickets (CRUD) 4.1 Create Ticket POST /api/tickets Bearer Token (Employee สร้างคำขอ)
4.2 List Tickets GET /api/tickets Bearer Token (ดึงตามสิทธิ์ผู้เรียก)
4.3 Assign Ticket PATCH /api/tickets/:id/assign Bearer Token (IT Support รับเคส)
4.4 Update Status PATCH /api/tickets/:id/status Bearer Token (เปลี่ยนเป็น RESOLVED)
5. Comments 5.1 Add Comment POST /api/tickets/:id/comments Bearer Token
5.2 View Comments GET /api/tickets/:id/comments Bearer Token
### 1.1 Admin Login # @name adminLogin POST http://localhost:{{$dotenv APP_PORT}}/admin/login Content-Type: application/json { "email": "{{$dotenv ADMIN_EMAIL}}", "password": "{{$dotenv ADMIN_PASSWORD}}" } ### 1.2 Admin Profile GET http://localhost:{{$dotenv APP_PORT}}/admin/users/me Authorization: Bearer {{adminLogin.response.body.access_token}} ### 4.1 Create Ticket (Employee) # @name createTicket POST http://localhost:{{$dotenv APP_PORT}}/api/tickets Content-Type: application/json Authorization: Bearer {{$dotenv USER_TOKEN}} { "title": "จอคอมพิวเตอร์เปิดไม่ติด มีไฟกระพริบสีส้ม", "description": "ใช้งานอยู่ดีๆ จอดับไป แผนกการเงิน ชั้น 3", "priority": "HIGH", "categoryId": "{{$dotenv CATEGORY_HARDWARE_ID}}" }
